Whister Infrastructure: Automated Update Matrix

This serverless directory serves as the official operational configuration record for Whister's automated update system. Background version tracking, binary distribution, and patch deployment routines are routed through these dedicated domain endpoints.

Network Routing & Asset Storage Mappings

All network traffic parameters are handled via our domain arrays to prevent heavy load dependency cycles on source code version repositories.

Target URL Subdomain / Path Backend Platform Architecture Functional Deployment Role
https://whisterbrowser.com Cloudflare Workers (Beta Staging Runtime) Intercepts incoming test client JSON strings, parses experimental version parameters, and serves beta patch manifests.
https://whisterbrowser.com Cloudflare R2 Storage Pool Delivers the production Windows background executable block to clients silently with zero egress fees.
https://whisterbrowser.com[version].patch Cloudflare R2 Storage Pool Provides compressed, raw structural text diff blocks for lightweight source patches.

Automated Execution Protocol Pipeline

The internal C++ thread layer coordinates with the network storage layout according to this three-tier execution loop sequence:

Stage 1: The Request The browser calls WhisterSettingsHandler::TriggerServerUpdateCheck, transmitting a quick payload string container to the staging subdomain:
{"version": "158.0.8105.0"}
Stage 2: The Parsing The Cloudflare Edge Beta Worker script interprets the JSON payload, cross-checks version strings, and replies with an update instruction block pointing to the staging patch assets.
Stage 3: The Deployment The browser client downloads the target chunk asynchronously into the local temp folder and executes the background process silently via base::LaunchProcess.
